# Ride Relief — 자전거 코스 3D 프린팅 MVP

Mac에서 실행하는 로컬 웹앱입니다. 남한 전체 지도에서 출발·도착과 출력 범위를 직접 정하고, 지형·건물·수면·코스를 STL 또는 3MF로 저장할 수 있습니다.

**웹에서 바로 실행:** https://rladbstn8090-source.github.io/ride-relief/

## 바로 실행

Node.js 20.19 이상(또는 22.12 이상)이 필요합니다. 폴더 안의 **Start Ride Relief.command**를 더블클릭하세요. 최초 실행 때만 패키지를 설치합니다. 실행 중인 터미널을 닫거나 Control+C를 누르면 서버가 종료됩니다.

휴대폰에서도 열려면 Mac과 휴대폰을 같은 와이파이에 연결하고 **Start Ride Relief - QR.command**를 더블클릭합니다. 자동으로 열린 화면 위쪽 **QR · 실행**을 누르고 QR을 스캔하세요. macOS 방화벽 질문이 나오면 Node의 로컬 네트워크 연결을 허용해야 합니다.

터미널에서 실행하려면:

```sh
npm ci
npm run dev -- --port 5173 --strictPort --open
```

주소: http://127.0.0.1:5173/ — 이 Mac에서만 접근하도록 설정되어 있습니다. 이미 서버가 실행 중이면 이 주소를 바로 여세요.

## 사용 순서

1. 앱을 열면 코스와 출력 범위가 없는 남한 전체 지도가 열립니다. 지도 위 **지역 찾기**에서 주요 도시를 클릭하거나 `부산 태종대`, `진주성`, 주소처럼 검색하면 해당 장소로 바로 확대됩니다. 주요 도시와 관광지는 인터넷 없이 이동할 수 있습니다.
2. **출발·도착 그리기** 상태에서 지도를 클릭합니다. 첫 클릭은 출발점, 마지막 클릭은 도착점이며 중간 클릭은 경유점입니다. 각 지점은 직선으로 연결됩니다. **한 점 취소**로 마지막 점을 되돌릴 수 있습니다.
3. 범위 모양에서 **직사각형·원·자유 영역** 중 하나를 고르고 **범위 선택**을 누릅니다. 직사각형은 두 모서리, 원은 중심과 가장자리, 자유 영역은 꼭짓점을 차례로 클릭한 뒤 **영역 완성**을 누릅니다. 점선 안쪽만 3D 지형으로 생성되며 받침대, 코스와 지물 모두 선택 외곽선으로 잘립니다.
4. 가장 긴 변, 지형·건물 높이 강조, 코스 두께, 건물·공원·수면·코스 표시를 조정합니다. 지형은 실제 해발 **200m 이하가 연두색**, **200m 초과가 초록색**으로 표시되며 공원·녹지도 200m 이하 지형과 같은 연두색을 사용합니다. 코스·범위·설정 변경은 잠시 뒤 **3D 미리보기에 자동 반영**됩니다. **3D 미리보기 새로고침**은 필요할 때 즉시 다시 만드는 버튼입니다.
5. 3D 미리보기에서 드래그로 회전하고 휠로 확대합니다.
6. **STL**은 단색 출력용 통합 입체, **3MF**는 레이어별 부품이 있는 다색 출력용입니다.
7. 상단 **저장 · 불러오기**에서 코스 이름을 입력해 현재 코스, 출력 범위와 모형 설정을 저장할 수 있습니다. 같은 주소를 다음에 다시 열어 저장 목록에서 불러오면 3D 미리보기가 다시 생성됩니다.

## VS Code와 GitHub Pages

- VS Code에서 이 폴더를 열고 **터미널 → 작업 실행 → Ride Relief: 실행**을 선택하면 로컬 앱이 실행됩니다. Chrome 디버그는 실행 및 디버그 화면의 **Ride Relief: Chrome에서 디버그**를 선택합니다.
- 휴대폰 연결용 서버는 **Ride Relief: 휴대폰 네트워크 실행** 작업을 사용합니다. 터미널에 표시된 Network 주소를 화면의 **QR · 실행**에 넣어 QR을 만들 수 있습니다.
- GitHub 저장소의 `main` 브랜치에 이 폴더를 올리면 `.github/workflows/deploy-pages.yml`이 검사와 빌드를 수행합니다. 저장소 **Settings → Pages → Source**에서 **GitHub Actions**를 선택하면 공개 URL이 생성됩니다.
- GitHub Pages 공개 주소에서는 누구나 앱 화면을 열 수 있습니다. 코스·범위 저장 데이터는 각 사용자의 브라우저 안에만 보관됩니다.

## Bambu Studio

- STL: mm 단위로 가져옵니다. 200m 경계를 기준으로 계산된 같은 지형 형상을 사용하지만 STL 규격에는 색상 정보가 없으므로 단색으로 열립니다.
- 3MF: 일반 모델로 열고 필요하면 부품 목록에서 `Terrain 0-200m`, `Terrain Above 200m`, Parks, Water, Buildings, Route에 필라멘트를 지정합니다. Parks는 `Terrain 0-200m`와 같은 연두색 재료를 공유하므로 파일의 고유 색상은 연두·초록·파랑·주황·건물색의 총 5개입니다. AMS 슬롯에는 자동 연결되지 않습니다.
- 프린터, 노즐, 필라멘트, 출력 품질 설정은 사용자가 선택합니다. 특정 프린터용 프로젝트나 G-code를 생성하지 않습니다.
- 기본 예제 크기: 약 **180 × 109 mm**. 출력 범위의 가로·세로 중 긴 쪽이 크기 슬라이더의 100–220 mm에 맞춰지므로 세로형 범위도 별도 수정 없이 출력판 안에 들어옵니다.
- `examples/jinju-180mm.stl`, `examples/jinju-180mm.3mf`는 출력 형식 검증용 파일입니다. 앱 시작 화면에는 불러오지 않습니다.
- 실제 프린터 출력은 수행하지 않았습니다. 출력 전 슬라이스 미리보기에서 세부 건물, 필라멘트 교체, 첫 레이어를 확인하세요.

## 데이터와 현재 한계

- 남한 전역의 AWS/Mapzen Terrarium 고도 타일을 로컬에 저장했습니다. 짧은 도시런부터 마라톤·자전거 종주까지 범위 크기에 따라 **192×192, 256×256, 288×288, 320×320 셀**을 사용합니다. 넓은 범위도 48×48 간략 지형으로 낮추지 않습니다. 온라인 고도를 우선 사용하고 서버를 사용할 수 없을 때만 같은 셀 수로 남한 로컬 실제 고도를 보간합니다.
- 건물·공원·녹지·강·호수·바다는 지역 구분 없이 공식 OpenStreetMap Shortbread 벡터 타일을 사용합니다. 선택 범위에 맞춰 가능한 가장 높은 지도 확대 단계부터 계산하고, 한 번에 최대 8장씩 순차적으로 받아 브라우저가 멈추지 않게 조립합니다. 마라톤 범위는 세부 건물 타일을 유지하고, 국토 종주처럼 출력 크기에 비해 개별 건물이 보이지 않는 범위에서만 낮은 지도 확대 단계로 자동 조정합니다.
- 새 영역은 가로·세로 **750 km**까지 지원합니다. 코스나 범위를 다시 수정하면 진행 중인 외부 지형 요청을 취소하고 최신 선택으로 다시 생성합니다. 넓은 범위는 수백 장의 지도 타일과 더 많은 삼각형을 처리하므로 완료까지 시간이 걸릴 수 있으며 화면에 진행 장수를 표시합니다.
- 외부 서버에는 지도 타일 좌표와 선택한 사각 영역만 요청합니다. 모델 생성과 내보내기는 로컬 브라우저의 Web Worker에서 수행합니다.
- 지역 검색은 사용자가 검색 버튼을 누를 때만 OpenStreetMap Nominatim에 한 번 요청하며 대한민국 결과로 제한합니다. 같은 검색어의 결과는 브라우저에 저장해 반복 요청을 줄입니다. 자동 완성 요청은 보내지 않습니다.
- 고도 셀 수는 가장 긴 실제 거리 기준으로 15 km 이하는 192, 60 km 이하는 256, 200 km 이하는 288, 그보다 넓으면 320입니다. 프린트용 지형의 최저점은 3 mm 받침대 위에서 시작합니다. 실제 해발고도를 그대로 프린트 Z 좌표로 쓰지 않습니다.
- 코스는 폭 0.8–4 mm, 지형 위 돌출 높이 1.2 mm입니다. 자동 도로 연결이나 자전거 길 탐색은 아직 없습니다. 사진과 GPX 가져오기는 상단 버튼에서 사용할 수 있습니다.
- 강·호수는 OpenStreetMap 윤곽을 지형 위 0.45 mm 돌출 레이어로 만들고, 바다는 고도 타일의 해수면을 판별해 3.45 mm 높이의 평평한 파란 레이어로 만듭니다. 선택 범위의 바깥 테두리까지 이어지는 큰 음수 고도 영역만 바다로 인정하므로 산속의 고립된 음수 픽셀은 물로 표시하지 않습니다. 바다가 포함되면 음수 해저 깊이는 0 m로 평탄화해 해저가 산처럼 솟지 않게 합니다.
- 상세 서버에서 받은 건물은 OSM의 `height`, `building:levels`, `roof:height` 순서로 실제 높이를 계산합니다. 광역시 벡터 타일에는 높이 속성이 없으므로 건물 면적과 고정된 변화를 이용해 8–42 m 범위의 시각적 높이를 만듭니다. **건물 높이 강조**에서 1–4배로 조정할 수 있고 출력 높이는 최소 0.8 mm입니다. 공원·정원·잔디·운동장은 별도 녹지 레이어로 표시합니다. 여러 선으로 나뉜 강둑은 이어 붙이고 수면 다각형의 내부 구멍을 유지해 선유도 같은 섬을 육지로 남깁니다. OSM에 없는 지물은 생성되지 않습니다.
- 저장하지 않은 편집 내용은 현재 페이지에서만 유지됩니다. 새로고침하면 빈 남한 전체 지도로 돌아갑니다.
- **저장 · 불러오기**로 저장한 코스는 현재 브라우저의 로컬 저장 공간에 최대 20개까지 유지됩니다. 저장 항목에는 코스, 출력 범위, 출력 크기, 지형·건물 높이 강조, 코스 두께와 레이어 설정이 포함됩니다. 이전 버전에서 저장한 코스도 새 건물·공원 기본값을 적용해 불러옵니다. 브라우저 데이터를 지우거나 다른 브라우저·Mac으로 옮기면 저장 목록은 전달되지 않습니다.
- 라이브 지도 탐색은 전 세계가 가능하지만 날짜변경선 횡단·극지방은 지원하지 않습니다.

## 구조와 GPX 확장 지점

```text
src/types.ts                공통 좌표·영역·레이어·모델 형식
src/data/jinju.ts            진주 저장 범위, 검증 경로와 거리 계산
src/data/korea.ts            남한 로컬 고도 범위
src/data/providers.ts        로컬 데이터 / 원격 고도·OSM 공급자
src/data/vector-features.ts  광역시 Shortbread 벡터 타일 조립
src/data/selection-area.ts   직사각형·원·자유 영역 계산
src/geometry/model.ts        닫힌 지형, 레이어, Boolean 결합·분할
src/geometry/export.ts       이진 STL, 표준 3MF 패키징
src/geometry/worker.ts       무거운 모델 연산을 별도 스레드에서 실행
src/ui/preview.ts            Three.js 렌더러와 카메라
src/main.ts                 지도 편집과 화면 상태 연결
public/data/jinju.json       저장된 진주 지형 데이터
public/data/terrain/9/       남한 전역 Mapzen Terrarium 고도 타일
```

사진·GPX 입력 화면은 `src/ui/route-import.ts`에 있습니다. 이미지 색상 분리·중심선 추출·좌표 변환은 `src/data/image-route.ts`에 분리되어 있습니다. 가져온 데이터는 기존 `Point[]` 형식으로 전달하므로 같은 지형·모형·내보내기를 사용합니다.

3D 형상은 Manifold의 Boolean 연산을 사용합니다. STL은 모든 레이어를 하나로 합칩니다. 3MF는 코스 > 건물 > 수면 > 지형 순서로 겹침을 제거하고 하나의 조립체에 넣어 상대 위치를 유지합니다. 면 맞닿음은 유지하므로 부품을 개별 배치하지 마세요.

자동 검사: 기본 예제, 크기 변경, 지형 강조, 선 두께 변경, 영역 잘라내기, 레이어 끄기, 해안 고도의 바다 판별·평탄화, 빈 경로·영역 밖 경로의 오류 처리, 모든 모서리에 두 면이 만나는 닫힌 메시, 양의 부피, STL 단일 연결체, 3MF 분할 부피 보존, 파일 패키지 구조.

Bambu Studio 2.8.2.61의 `--info`로 두 예제를 읽어 **manifold = yes** 및 mm 크기를 확인했습니다. STL은 연결된 한 부품입니다. 3MF의 연결된 덩어리 수는 개별 건물·하천 섬 때문에 많을 수 있으며 레이어 개수와 다릅니다.

선택적으로 WebMCP 지원 브라우저에는 읽기(`read_route_model`)와 현재 설정으로 생성(`generate_route_model`) 도구가 등록됩니다. 지원하지 않는 브라우저에서는 일반 UI만 동작합니다.

## 사진·GPX 가져오기

상단 **사진 · GPX 가져오기**에서 PNG / JPG / WebP 스크린샷이나 `.gpx` 파일을 선택합니다. 파일은 최대 15 MB입니다.

### 네이버 지도 길찾기 사진

1. 네이버 지도에서 자전거 또는 도보 길찾기 결과가 전체 화면에 보이도록 캡처합니다.
2. 사진을 선택하면 굵은 파란 경로와 안쪽의 흰 방향 화살표를 하나의 선으로 자동 인식합니다. 자동 실행되지 않으면 **네이버 파란 경로 자동 인식**을 누릅니다.
3. **위치 맞추기 시작**을 누르고 출발·도착 핀 끝이나 멀리 떨어진 교차로 두 곳을 `사진 A → 실제 지도 A → 사진 B → 실제 지도 B` 순서로 맞춥니다.
4. 지도 위 주황색 코스를 확인하고 적용하면 코스 전체 범위와 남한 로컬 실제 고도가 곧바로 3D 미리보기에 반영됩니다. 부산–진주처럼 긴 코스는 건물을 생략한 간략 지형으로 표시됩니다.

제공된 부산–진주 네이버 길찾기 화면은 900 px 분석 크기에서 105개 굴곡점으로 복원해 파란 선 전체를 추적하는 것을 확인했습니다.

### Nike Run Club 등 다른 운동 앱의 코스 사진

1. 앱에서 **지도와 코스 선이 보이는 스크린샷**을 저장합니다. 일반 풍경·운동 인증 사진이나 지도 없는 통계 화면으로는 경로를 복원할 수 없습니다.
2. 사진을 선택하고 **선 색상 선택** 상태에서 코스 선의 가운데를 클릭합니다. 필요하면 **지도만 자르기**로 범례·버튼·텍스트를 제외합니다.
3. **코스 선 분석**을 누르면 해당 색상의 가장 큰 연결 영역을 중심선으로 추출합니다. 색상 허용 범위를 조절할 수 있습니다. 추출 선은 밝은 청록색으로 겹쳐 표시됩니다.
4. 여러 색으로 된 페이스 선, 교차·왕복 경로, 끊긴 선은 자동 분석이 실패할 수 있습니다. **직접 따라 그리기**로 사진 위 코스를 실제 순서대로 클릭합니다. 순환 코스는 마지막 점을 출발점에 찍습니다. 최대 500개 점을 사용합니다.
5. **위치 맞추기 시작**을 누른 뒤 화면 안내에 따라 `사진 A → 지도 A → 사진 B → 지도 B`를 순서대로 클릭합니다. 두 번째 지도 점까지 지정하기 전에는 좌표를 계산하지 않습니다. 지도는 드래그·확대하거나 위도·경도로 이동할 수 있습니다.
6. 지도 위 주황색 코스가 어긋나면 A·B 핀을 끌어 기준점을 조정하거나 **지도에서 코스 세밀하게 수정**을 누르고 흰색 조절점을 끕니다. 조절점 주변의 경로가 부드럽게 따라 움직이며, **지도 수정 취소**로 직전 수정을 되돌릴 수 있습니다.
7. 예상 코스를 확인하고 확인란을 체크한 뒤 **이 코스를 지도에 적용**을 누릅니다. 원래 코스는 이때에만 대체됩니다. 적용된 코스와 자동 계산된 범위는 3D 미리보기에 바로 반영됩니다.

분석은 외부 AI 서비스 없이 브라우저 내 색상·연결선 분석으로 수행합니다. 사진 파일 자체는 업로드하지 않습니다. 자동 지명 인식·OCR·GPS 위치 추론·Nike 계정 연동은 없습니다. 기준점 두 곳으로 Web Mercator 좌표에서 회전·축척·위치를 맞추며, 원근이 있는 3D 지도나 비균일하게 늘어난 사진은 정확하게 맞출 수 없습니다. 선이 겹치는 곳의 실제 진행 순서, 페이스, 운동 시간, 실제 GPS 기록은 사진만으로 복원하지 않습니다. 지도 타일과 적용 후 지형 요청에는 선택한 위치가 사용됩니다.

### GPX

GPX의 track segment / route 좌표를 읽습니다. 여러 구간은 드롭다운으로 하나씩 선택하고 임의로 이어 붙이지 않습니다. 500개를 넘는 좌표는 균등 간격으로 줄여 미리보기·모형에 사용하므로 세부 굴곡과 거리에는 오차가 생길 수 있습니다. 고도는 기존 지형 공급자를 사용하고 GPX의 기록 고도·시간·페이스는 가져오지 않습니다. 앱별 GPX 내보내기 가능 여부는 다르며 이 앱은 각 운동 계정에 직접 연결하지 않습니다.
